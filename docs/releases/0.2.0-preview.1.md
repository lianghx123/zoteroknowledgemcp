# Zotero Knowledge MCP 0.2.0-preview.1

Source-preview scope for version 0.2.0-preview.1. No installer or matching
release tag is currently published. The source provides the local Zotero PDF
knowledge workflow; it does not complete the full migration roadmap.

## Included

- Independent knowledge libraries/folders, native item admission, continuous
  collection synchronization, processing tasks and knowledge Trash recovery.
- PaddleOCR-VL-1.6 and MinerU `vlm` parsing with restart/retry/cancel handling,
  ordered structured content and local document assets.
- Profile-bound embeddings, persistent USearch, full-text/semantic/fusion
  retrieval, optional reranking and traceable source evidence.
- Markdown PDF companion with math, tables/images, outline, citation previews,
  saved reading preferences and document-scoped search.
- Block editing, block types, insertion/deletion, undo/redo and explicit document
  save with conflict detection, transactional text indexing and compatible vector
  reuse. Unsaved edits are discarded when the PDF reader closes or the plugin
  restarts.
- All 16 local MCP tools, contract 2.4.0, library-scoped personal tokens,
  bounded/continued reading and version-checked annotation/summary writes.
- English, Simplified/Traditional Chinese, German, French, Spanish and Japanese
  interface catalogs.

## Install or Upgrade

Requires **Zotero 10.0.x**. Native development verification used Windows and
Zotero 10.0.6–10.0.8; equivalent acceptance on other operating systems is pending.
End users do not need Node.js, npm, Python or a local helper process.

1. Close Zotero and keep an external backup of its data directory, including
   `knowledgemcp/`, before replacing a development build.
2. When a reviewed release is available, download **zotero-knowledge-mcp.xpi**
   from its release page; private repositories require an authorized account. Source archives are for
   developers and are not installable plugins. `SHA256SUMS` provides the XPI hash.
3. Open **Tools → Plugins → gear menu → Install Plugin From File…**, select the
   XPI and restart if requested. The plugin ID remains
   `zotero-knowledge-mcp@local.dev`, so this replaces the earlier development build.
4. Open **Zotero Settings → Knowledge MCP** to configure the desired services.
   New installations start with parsing, embedding and MCP disabled. Compatible
   parser/model services and credentials are needed for provider-backed actions.
5. Enable local MCP only when needed and issue a token for explicit knowledge
   libraries. Its default endpoint is `http://127.0.0.1:23126/mcp/knowledge`.

Preview upgrades require downloading and installing the newer XPI manually.
The update feed currently advertises no stable upgrade; private repository
assets require repository access.

Parsing sends selected PDF bytes to the configured parser. Semantic queries
send query text to the embedding provider; optional reranking can send document
passages. Configure these services deliberately. Local index repair reuses
stored vectors without regenerating embeddings.

## Known Limits

- Approximately 1,000-paper end-to-end acceptance, independent relevance labels
  and agreed performance budgets remain pending. The saved 100,000-vector
  benchmark measures index behavior, not full-workflow paper capacity or human
  search accuracy.
- Direct import of user-generated parsing results, broader source/edit/review
  parity and integrated full backup/restore tooling remain deferred or incomplete.
- Pre-upgrade database snapshots do not back up every artifact or protect
  against Zotero data-directory/account reset. Installing an older XPI alone
  does not downgrade a newer schema; restore requires compatible external data.
- MCP supports same-machine loopback access while Zotero is running. Public
  HTTPS, account/relay access and cloud synchronization are unavailable.
- Long-running/cross-platform, OS-level crash and exhaustive manual locale/UI
  acceptance remain open. Native API/DOM checks are not exhaustive manual tests.

## Verification and Guides

Source validation includes type checking, production packaging, the full Node
suite and database consistency checks (16 migrations, 56 typed tables).
Every future installer requires its own exact-package validation. Native Zotero
and client interoperability checks retain their stated scope; this source preview
makes no new provider-quality or scale claim.
